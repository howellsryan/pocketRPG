Dark Mode

The iron skin was never removed. It has been sitting under the parchment since the Forgemark pilot, waiting to be asked for.

Theme
01

Every screen is already painted twice

DESIGN.md §2 calls it the Two-Skin Trap: each screen-prefixed class is defined once as the pre-Forgemark iron skin, then again as a .forge-shell parchment override. The game runs light because 30 of 40 screens opt into that override.

Dark mode is not new art direction. It is making the override layer conditional and repairing the iron skin where it has rotted from disuse.

02

One semantic layer, twelve tokens

The raw palette never flips. --fm-ink means the dark brown ink colour — it is also the text on a brass button face, so inverting it produces cream on cream. Components stop reading the palette and read these instead.

Semantic tokenLightDarkOn ironWCAG AA
--surface-pagevellum → soot——
--surface-panelparch → iron——
--text-strongink → parch12.8:1Pass
--text-softink-soft → rule6.9:1Pass
--text-faintink-faint → new5.2:1Pass
--accentember-deep → ember-hi6.0:1Pass
--accent-metalbrass-lo → brass-hi10.4:1Pass

Nine of twelve are free

Only --text-faint, --rule and --surface-raised need new values on dark. Everything else is an existing token re-pointed — the palette carries enough mid-tone that inversion is a swap of the two extremes.

The button system costs nothing

Scoping the parchment button block to light is the whole change. Under dark, .forge-shell and .fm-parch inherit the iron button tokens that already sit at :root. Zero new declarations for every button, toggle and tile in the game.

05

What breaks

Three real failures, not hypotheticals. Switch this page to dark to see the first two disappear.

Every stat number on the combat screen

--fm-ember-deep is the value colour for .cb-kstat__v, .cb-stat__v and .cb-mon__kc. On iron it measures 1.8:1 — effectively invisible.

Kills 2,481 1.8:1
Kills 2,481 6.0:1

Faint labels fall a step short

--fm-ink-faint #8a7553 reads 4.2:1 on iron — under the 4.5:1 floor. Lightening to #9d8862 clears it at 5.2:1 without changing the tone.

Level 86 · 111 HP 4.2:1
Level 86 · 111 HP 5.2:1

Two item tiers vanish

--tier-cryptbound and --tier-dhide-black are both #1f1f1f — near-identical to the iron panel behind them. The tint is data, so it must not change: add a theme-conditional hairline instead.

Bare, then outlined

Never flips

HP and XP bar colours are safety semantics, already exempt from the forge repoint. Item tier and potion tints are data encodings. PlaceArt.jsx is illustration — check its scrim, don't recolour the art.

06

Order of work

  1. Token layerAdd layer 2 to :root with today's light values. Screenshots must come out pixel-identical — this phase changes nothing.
  2. Plumbingsrc/utils/theme.js, plus a pre-paint stanza in build_single.cjs's <head>. It must sit above #app-splash, which paints before the existing body scripts and would otherwise flash parchment.
  3. The flipScope the parchment button block and the 45 forge overrides to light. Give .fm-parch its iron material.
  4. The auditAll 40 screens and 71 components in dark, ordered by rule count: cb-, wm-, clog-, the fm- kit, lm-. This is the bulk of the task, not a polish pass.
  5. SettingsA three-way Light / Dark / System control on the Settings screen. Preference lives in localStorage — the save blob is locked during PvP, co-op and open-world sessions, so a theme changed mid-fight would silently revert.
  6. GuardsA token-parity test and a hardcoded-colour test, both build-failing, in the shape of questGateProduction.test.ts. The colour allowlist starts at today's state and only ever shrinks.

Out of scope: the open-world companion, the admin portal, and the pre-login landing screens. Full plan in docs/dark-mode-plan.md.
