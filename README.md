# PocketRPG

Menu-driven, tick-based, mobile-first fantasy idle RPG built with deterministic core logic and offline-first persistence.

**Live build**: https://pocketrpg.pages.dev

---

## 1) Project Overview

PocketRPG is a simulation-first RPG where progression (combat, skilling, gathering, raids, minigames, quests) advances on a global **600ms tick**. The codebase is organized to keep game logic deterministic and testable while allowing lightweight UI iteration.

Key design goals:
- **Mobile-first UX** (touch targets and responsive layout).
- **Offline-first gameplay** (IndexedDB/localStorage mirrors).
- **Cloud-aware saves** for multi-session continuity.
- **Deterministic simulation** for regression-safe balancing.

---

## 2) Tech Stack

- **UI**: Preact
- **Bundling**: Vite
- **Language**: JavaScript + TypeScript transpile pipeline for single-file output
- **Persistence (local)**: IndexedDB via `idb`, with selected localStorage mirrors
- **Persistence (cloud)**: API-backed save blob synchronization
- **Testing**: Vitest
- **Styling**: Tailwind CDN + CSS variables

---

## 3) Repository Layout

- `src/engine/` — pure gameplay logic (no UI imports)
- `src/screens/` — top-level feature screens (combat, skilling, gather, etc.)
- `src/components/` — reusable UI components
- `src/state/` — app context and state wiring
- `src/cloud/` — sync, APIs, cloud-side workflows
- `src/db/` — client persistence and save/load plumbing
- `src/data/` — static content definitions (items, monsters, skills, clues, raids, …)
- `tests/` — logic and regression test suite
- `migrations/` — server/data migration history

## 5) Save System & Cloud Sync (Developer Notes)

PocketRPG uses a **hybrid save strategy**:

1. **Local-first writes** for immediate gameplay continuity:
   - Stats/inventory/equipment/bank/settings are persisted locally through state-level dirty tracking + debounced writes.
2. **Cloud push/pull sync** for account continuity across refreshes/devices:
   - Snapshot-based payloads are pushed through cloud sync utilities.
   - Pull/merge paths are used on boot and conflict checks.

### Cloud save trigger model

Cloud saves are intentionally **event-driven + heartbeat-based**:

- **Critical instant-save events** (coalesced):
  - Monster kill
  - Clue reward completion
  - Minigame completion
  - Other milestone reasons (level ups, boss/raid completions, etc.)
- **Active activity heartbeat**:
  - While active progression tasks are running (`skill`, `gather`, `agility`, `thieving`, `hunter`, `minigame`), a cloud save request is issued every **30 seconds**.

This avoids hardcoding every action and keeps onboarding simple: if new content reuses these task areas/reason hooks, cloud persistence behavior is inherited automatically.

### Cloud save status UX

The top header shows cloud status states:
- Saving spinner when actively pushing.
- Saved confirmation on success.
- **Out of Sync** indicator when local progress has unsynced cloud changes.

## 6) Gameplay Determinism Rules (Important)

- Global tick cadence: **600ms**
- Use `Math.floor()` for gameplay rounding
- XP/level caps and formulas are standardized in engine logic
- Inventory slot cap is hard-limited
- Idle simulation applies deterministic outcome rules

When adding mechanics, preserve deterministic ordering and avoid UI-driven side effects in engine modules.

## 7) Contributor Workflow

1. Make targeted changes in `src/**` (avoid broad refactors).
2. Add/update tests for new gameplay behavior.
3. Run:
   - `npm test`
   - `npm run ci`
4. Keep generated artifacts policy in mind:
   - Root `index.html` is generated by rebuild flow; do not casually hand-edit.

---

## 8) Common Troubleshooting

- **Cloud mismatch after long background time**: verify sync status indicator and check save push events.
- **Single-file build errors (duplicate identifiers)**: dedupe top-level declarations; prefer shared helpers.
- **Idle progress anomalies**: validate active task mirrors and idle simulation inputs.

---

## 9) Security & Authority Model (High-level)

- Treat client state as untrusted for economy/progression-critical outcomes.
- Server/API paths should authoritatively validate protected mutations.
- Save revision and stale-write protection are part of cloud integrity.

---

## 10) Where to Start (New Contributors)

Suggested onboarding path:
1. Read `src/state/gameState.jsx` for app-level state and persistence flow.
2. Read `src/cloud/sync.js` for cloud push/pull mechanics.
3. Read one feature vertical (e.g., `src/screens/CombatScreen.jsx` + `src/engine/combat.js`).
4. Run tests and inspect a few targeted specs in `tests/`.
